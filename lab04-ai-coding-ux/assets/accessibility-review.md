# Accessibility Review — ระบบจัดการ Stock RAM

## ผลการตรวจสอบ Accessibility Checklist 

จากการตรวจสอบ Mockup ระบบจัดการ Stock RAM ตามหลัก Accessibility พบประเด็นที่ต้องปรับปรุงบางส่วน โดยได้บันทึกข้อผิดพลาดที่พบจาก AI พร้อมแนวทางการแก้ไขไว้ดังนี้

| รายการตรวจสอบ                                                  | ผลการตรวจ | รายละเอียดและการแก้ไข                                                                                                                                                                                                                                                                                                                          |
| -------------------------------------------------------------- | :-------: | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **1. ข้อความหลักบนพื้นขาวมี Contrast อย่างน้อย 4.5:1**         | ❌ ไม่ผ่าน | **จุดที่ AI ทำพลาด:** พบการใช้สีเทาอ่อนกับข้อความหลายจุด เช่น หัวตาราง **ชื่อ RAM, Serial Number** และป้ายสถานะ **RAM UNKNOWN** ทำให้ Contrast Ratio ต่ำกว่า 4.5:1 และอ่านได้ยาก<br><br>**การแก้ไข:** เปลี่ยนข้อความบนพื้นขาวจากสีเทาอ่อนเป็น **Text `#111827`** ตาม Design System เพื่อให้มี Contrast ที่เหมาะสมและผ่านเกณฑ์ WCAG AA          |
| **2. ปุ่มหลักมี Contrast เพียงพอ**                             |   ✅ ผ่าน  | ปุ่มหลัก เช่น **ค้นหา, ขาย และยืนยันการขาย RAM** ใช้สี **Primary `#1E40AF`** ร่วมกับตัวอักษรสีขาว ทำให้มี Contrast เพียงพอ จึงไม่จำเป็นต้องแก้ไข                                                                                                                                                                                               |
| **3. ทุกช่องกรอกมี Label ที่มองเห็นได้**                       | ❌ ไม่ผ่าน | **จุดที่ AI ทำพลาด:** ช่องค้นหาในหน้า Dashboard ใช้เพียง Placeholder **"ค้นหา RAM หรือ Serial Number..."** โดยไม่มี Label ที่มองเห็นได้ เมื่อผู้ใช้เริ่มกรอกข้อมูล Placeholder จะหายไป ทำให้ไม่สามารถใช้เป็นตัวระบุบริบทของช่องได้อย่างเหมาะสม<br><br>**การแก้ไข:** เพิ่ม Label **"ค้นหาสินค้า"** ไว้ด้านบนหรือด้านหน้าของช่องค้นหาอย่างชัดเจน |
| **4. ช่องที่บังคับกรอกมีสัญลักษณ์ชัดเจน**                      | ❌ ไม่ผ่าน | ในหน้าขาย RAM ช่อง **Serial Number RAM** เป็นข้อมูลที่จำเป็นต้องกรอก แต่ไม่ได้มีสัญลักษณ์แสดงว่าเป็นช่องบังคับกรอก<br><br>**การแก้ไข:** เพิ่มเครื่องหมาย **`*`** หรือข้อความ **`(จำเป็น)`** ใน Label เพื่อให้ผู้ใช้ทราบว่าต้องกรอกข้อมูลก่อนดำเนินการต่อ                                                                                       |
| **5. Error ไม่ได้ใช้สีเพียงอย่างเดียว**                        |   ✅ ผ่าน  | ข้อความแจ้งเตือนใช้ **ไอคอน ⚠️ ร่วมกับข้อความ** และสี **Warning `#B45309`** ทำให้ผู้ใช้สามารถเข้าใจสถานะของ Error ได้โดยไม่ต้องอาศัยสีเพียงอย่างเดียว จึงผ่านเกณฑ์                                                                                                                                                                             |

## สรุปผลการตรวจสอบ

จากการตรวจสอบ Accessibility ของ Mockup ระบบจัดการ Stock RAM พบประเด็นที่ต้องปรับปรุงหลัก ๆ ได้แก่

* **Contrast:** สีเทาอ่อนบางส่วนมี Contrast ไม่เพียงพอ จึงเปลี่ยนเป็น `#111827`
* **Label:** ช่องค้นหาใช้ Placeholder แทน Label จึงเพิ่ม Label **"ค้นหาสินค้า"**
* **Required Field:** ช่อง Serial Number RAM ไม่มีตัวระบุว่าจำเป็น จึงเพิ่ม `*` หรือ `(จำเป็น)`
* **Error Message:** มีการใช้ไอคอนและข้อความร่วมกับสี จึงผ่านเกณฑ์ด้านการสื่อสาร Error
* **Button Label:** ปุ่ม **"ตกลง"** ใน Error Modal ไม่สื่อถึงการกระทำ จึงเปลี่ยนเป็นข้อความที่ชัดเจนกว่า

### ผลการประเมินโดยรวม

การตรวจสอบช่วยให้สามารถระบุและแก้ไขข้อผิดพลาดด้าน Accessibility ที่เกิดขึ้นใน Mockup ได้อย่างเป็นรูปธรรม โดยเฉพาะเรื่อง **Contrast, Label, Required Field และข้อความบนปุ่ม** เพื่อให้ UI รองรับการใช้งานของผู้ใช้ได้หลากหลายมากขึ้นและสอดคล้องกับหลัก WCAG ระดับ AA
